The details pane: ending tab-hopping in the desktop app

In the PROTECT Windows desktop app, staff had to click through several tabs to see synced data for one case, then come back to the grid and repeat it for the next row. I designed a collapsible details pane that sits under the grid and follows the selected row.

Research

Watching the detour

I worked from stakeholder input and from walking through the existing desktop journey with the business analyst. I counted the clicks needed to answer everyday questions about a case and noted where people lost their place.

Objectives

Four goals

Details instantly visible

Everything key in one place, with no navigation.

Collapsible sections

Manage information overload for data-heavy records.

Fit desktop standards

Respect Windows and government system limits.

Visual clarity

Clear headings, spacing and hierarchy.

Constraints & trade-offs

Modern UX inside a legacy desktop app

Animated drawer vs. static sections

OptionA sliding drawer with hover reveals
ChosenStatic expand/collapse, click and keyboard only

The Windows rendering environment restricted animation and hover states, so every interaction had to work without them.

New look vs. familiar look

OptionA fresh visual style for the pane
ChosenMatch the existing app and improve spacing and hierarchy

The pane had to feel like part of the app people already knew, just clearly better.

Design first, check later vs. check every element

OptionDesign freely, then negotiate with developers
ChosenConfirm each element is feasible before adding it

Legacy components limited what could be built. Checking early meant nothing approved had to be cut.

Formal usability tests vs. close observation

OptionWait for formal testing slots
ChosenFrequent reviews and observation with BA and developers

Testing access was restricted, so I tested often in smaller ways and planned validation carefully.

Design solutions

Five changes that fixed it

  1. Collapsible panels hide or expand groups, reducing visible complexity without removing any data.
  2. Fields ordered by use, so the most-referenced information comes first.
  3. Context sync from the grid: jurisdiction, case type and status update when a row is selected.
  4. Consistent spacing, headers and grouping so the pane can be scanned quickly.
  5. Resizable layout tested at the window sizes and monitor setups used in DA offices.
Outcome & reflection

Fewer clicks, no tab switching

Staff can now see important case data without leaving the grid. The pane was built, went through QA testing with the BAs, and is live in the desktop app.

  • Modern UX in a legacy desktop app needs developers involved from day one.
  • Clear communication with the BA is essential when platform limits shape the design.
  • Collapsible patterns work well in data-dense government tools with fixed screen space.
